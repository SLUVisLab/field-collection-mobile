# M6.2C Collect Entity Characterization

**Status:** source-derived reference behavior; not a Gather runtime result
**Collect source:** `getodk/collect` commit
`ed2e97154df22cde4ce444cc49cd11cf3a6514fc`

This bounded characterization records the offline Entity behavior Gather must
match once it receives authoritative resolved Entity effects from the engine.
It is not application logic and does not make Gather responsible for XForms
semantics.

## Source basis

Collect imports server Entity CSV data into its local Entity repository, then
provides a synthesized secondary instance to forms. It does not edit the
downloaded CSV resource:

- `entities/src/main/java/org/odk/collect/entities/javarosa/intance/LocalEntitiesInstanceProvider.kt`
  lines 20-35
- `entities/src/main/java/org/odk/collect/entities/javarosa/intance/LocalEntitiesInstanceAdapter.kt`
  lines 46-81

The synthesized row has these system columns in addition to authorized
properties:

```csv
name,label,__version,__trunkVersion,__branchId
```

`EntitySchema.kt` lines 3-8 declares these names. `LocalEntityUseCases.kt`
lines 62-100 and 119-166 establishes the import, create, and update behavior
below.

## Sanitized six-case fixture

Seed Entity List delivered by Central:

```csv
name,label,__version,full_name
11111111-1111-4111-8111-111111111111,Server-0,7,Server-0
```

For deterministic illustration:

```text
S  = 11111111-1111-4111-8111-111111111111
BS = 22222222-2222-4222-822222222222
C  = 33333333-3333-4333-8333-333333333333
BC = 44444444-4444-4444-8444-444444444444
```

`BS` and `BC` are stand-ins for branch UUIDs generated by Collect.

| Case | Finalized Entity XML | Effective row after finalization |
| --- | --- | --- |
| Imported server baseline | None | `S,Server-0,7,7,BS,Server-0` |
| Offline create `C` | `<entity dataset="people" create="1" id="C"><label>Created-0</label></entity>` | `C,Created-0,1,,BC,Created-0` |
| First offline update `C` | `<entity dataset="people" update="true" id="C" baseVersion="1" trunkVersion="" branchId="BC"><label>Created-1</label></entity>` | `C,Created-1,2,,BC,Created-1` |
| Second offline update `C` | `<entity dataset="people" update="true" id="C" baseVersion="2" trunkVersion="" branchId="BC"><label>Created-2</label></entity>` | `C,Created-2,3,,BC,Created-2` |
| First offline update `S` | `<entity dataset="people" update="true" id="S" baseVersion="7" trunkVersion="7" branchId="BS"><label>Server-1</label></entity>` | `S,Server-1,8,7,BS,Server-1` |
| Second offline update `S` | `<entity dataset="people" update="true" id="S" baseVersion="8" trunkVersion="7" branchId="BS"><label>Server-2</label></entity>` | `S,Server-2,9,7,BS,Server-2` |

All rows use this header:

```csv
name,label,__version,__trunkVersion,__branchId,full_name
```

The server Entity remains alongside the locally-created Entity in the
effective data through every case.

## Qualifications

Attribute presence and lexical values are authored by the XForm. Collect
materializes local Entity state; it does not add attributes to submission XML.

- The upstream registration fixture uses `create="1"` and contains no
  `baseVersion`, `trunkVersion`, or `branchId`:
  `test-forms/src/main/resources/forms/one-question-entity-registration.xml`
  lines 13-27.
- The upstream update fixture uses `update="true"` and binds ID/version/branch
  attributes from the selected effective row:
  `test-forms/src/main/resources/forms/one-question-entity-update.xml`
  lines 13-30.
- Gather's prior stock-engine device artifact uses the equivalent lexical
  `update="1"` and serializes empty trunk/branch attributes when its supplied
  field-client CSV does not contain the offline system columns:
  `archive/experiments/m2.4-webview-xforms-sidecar/out/m466-ios-runtime-result.json`.
- Collect's finalization processor extracts the action, dataset, ID, label,
  and **relevant** `entities:saveto` property values:
  `entities/src/main/java/org/odk/collect/entities/javarosa/finalization/EntityFormFinalizationProcessor.kt`
  lines 13-46 and `FormEntity.kt` lines 1-8.

## Evidence boundary

Gather has device/runtime proof that the stock engine produces create XML and
Central accepts it. The local-row evolution documented here is authoritative
Collect source analysis, not an executed Collect Android runtime capture. A
full Collect Gradle environment was deliberately not introduced just to
duplicate this bounded reference behavior.
