# M5.4 durable instance lifecycle

`instances` migration 4 stores only searchable lifecycle metadata: a local
instance ID, ODK `instanceID`, project/form IDs, the exact immutable
`form_version_id` plus source version/hash, state, durable XML relative key,
timestamps, and sanitized send receipt/error. No answer table exists.

The XML file is authoritative. Saving serializes through the public XForms
store/host, atomically writes `projects/<project>/instances/<local>/instance.xml`,
then records SQLite metadata. Resuming reads that XML and calls public
`loadInstance(xml, instanceXml, attachments)`, which delegates to engine
`restoreInstance`; values, repeats, Entity choices, metadata, and instance ID
are never reconstructed with `setValue`.

Drafts can be saved, continued, or explicitly discarded on exit. Finalization
uses the engine serialization validation result and cannot enter `ready` with
violations. Sending one/all is a foreground user action through
`OdkCentralClient.submit({ xml, attachments })`. Failed sends remain `ready`
with redacted error text for explicit retry; successful sends are durable `sent`
records and retain XML.

### Camera-backed image attachment

Migration 5 stores a per-instance mapping from an upload reference to a safe
filename, MIME type, and Gather-relative media key. VisionCamera capture returns
only a plain local-file result (`uri`, `file`, `path`, content type, and available
dimensions), never a camera-native object. `FormRunner` resolves that local URI
to an `expo-file-system` `File` for `attachImageMedia()`, which copies it into
`projects/<project>/media/<instance>/`, binds the generated safe filename in
engine XML, and persists the draft XML and media metadata. Draft discard deletes
copied media; project removal deletes the whole project tree. Deterministic
fixture images remain gate-only. Gallery/file picking, general media management,
and background upload/retry are not implemented. Non-image uploads remain
unsupported. Migration 6 clears a project's instances before immutable form
versions cascade, allowing project removal to delete media metadata and the
durable project media directory together.
